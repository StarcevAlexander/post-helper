# Готовый контент: съёмка в приложении и обработка на ПК

Мастер в списке съёмки на неделю нажимает «Снять» у кадра, снимает фото или видео камерой телефона, и файл уходит на сервер. Воркер на вашем ПК забирает его, расшифровывает речь, спрашивает у сервера план правки (модель z.ai GLM-5.3-Flash смотрит превью и речь: пресет цвета, фокус кадрирования, заголовок, чистые субтитры), ffmpeg режет под формат публикации, накладывает цвет, субтитры и заголовок и отдаёт результат обратно. Мастер видит экран «Готовый контент», смотрит, сохраняет в телефон и публикует сам. Когда очередь мастера пуста, ему приходит пуш «Контент готов».

Над кнопками «Снять» у каждой публикации есть поле «Что хотите сказать в этой публикации»: мастер пишет своими словами, текст уходит вместе с файлом, и модель z.ai переписывает его в продающую подпись (крючок, польза, призыв записаться; без хэштегов, 400–700 знаков, ничего не выдумывая про услуги и цены). Подпись показывается на экране «Готовый контент» в секции «Текст для публикации» и копируется вместе с хэштегами комплекта; без текста мастера подпись не пишется. Если модель недоступна, подпись равна тексту мастера как есть.

Размеры результата: Reels и сторис 1080×1920, пост 1080×1350. Видео H.264 (NVENC, при сбое libx264) + AAC, фото JPEG.

## Что стоит на ПК

- `ffmpeg`/`ffprobe` 8 (сборка gyan full: фильтры `ass`, `eq`, `colorbalance`, `unsharp`, энкодер `h264_nvenc`).
- `whisper` (openai-whisper, Python 3.11, CUDA). Модель по умолчанию `large-v3-turbo` из `~/.cache/whisper`; другая задаётся `WHISPER_MODEL`. Если свободно меньше 4 ГБ видеопамяти (например, рисует воркер референсов), речь расшифровывается на процессоре моделью `small`.
- Шрифт субтитров `Arial` (переопределяется `MEDIA_FONT`).

## Сервер

- Оригиналы и результаты лежат на диске в `MEDIA_DIR` (по умолчанию `media` в рабочей папке сервера, то есть `server\media`). Папка не в git. В `server\.env` на боевом ПК задайте `MEDIA_DIR=C:\post-helper-media`, чтобы файлы не жили в репозитории.
- Оригинал удаляется сразу после обработки. Готовые и неудавшиеся записи старше `MEDIA_KEEP_DAYS` (по умолчанию 30) удаляются раз в сутки вместе с файлами.
- Лимиты: файл до 300 МБ, у мастера не больше 60 записей (лишнее мастер удаляет сам на экране «Готовый контент»).
- Таймауты публичного порта подняты до 10 минут: загрузка видео с телефона через Funnel идёт медленно.
- Копия базы (`tools/server/backup.ps1`) файлы не включает: раз в неделю копируйте `MEDIA_DIR` вместе с `C:\post-helper-backups`.
- Список всех записей: `GET http://127.0.0.1:8081/api/admin/media`.

## Включение воркера

```
powershell -File tools/media/autostart.ps1 install
```

Ставит задачу `PostHelperMediaWorker` без прав администратора и без окна (через `tools/hidden-task.ps1`): стартует при входе в систему, раз в 5 минут задача поднимает упавший процесс. Лог: `tools/media/worker.log`. `status` показывает задачу и процесс, `uninstall` снимает задачу и останавливает воркер.

Вручную: `node tools/media/worker.mjs --once` (один пункт и выход), `--interval 60` (пауза между опросами, с). Адрес сервера по умолчанию `http://127.0.0.1:8081`, другой задаётся `AGENT_SERVER` в `tools/agent/.env`.

Проверка без сервера: `node tools/media/worker.mjs --sample путь\к\файлу --format reels --out папка`. Делает результат по запасному плану (пресет `clean`, фокус по центру), с расшифровкой речи, если в видео есть звук.

Тесты: `node --test "tools/media/*.test.mjs"`.

## Что прислали мастера

Админка: откройте на этом ПК `http://127.0.0.1:8081/admin/`. Слева список мастеров (поиск по имени, городу, id), справа карточка мастера: контент с просмотром фото и видео и скачиванием готового и оригинала, план с отметками, заявки, обратная связь, история уведомлений с актуальностью, профиль (стратегия, рекомендации, итоги месяца, выгрузка всего о мастере). Страница только читает данные и открывается только с этого компьютера: админский порт не виден снаружи, а изменить через неё ничего нельзя.

`node tools/owner/owner.mjs media [id или часть имени]` показывает загрузки мастеров, новые сверху: дата, публикация, фото или видео, статус, текст мастера, что сделала обработка, сколько раз переделывали и последнее пожелание, ошибка. `--save [папка]` скачивает готовые файлы (по умолчанию в `tools/owner/media/<id мастера>/`), `--source` добавляет оригиналы, пока они хранятся. Без имени показывает всех мастеров.

Мастер может трижды попросить «Переделать» готовый файл с пожеланием: оригинал хранится до конца срока хранения контента, пожелание уходит в запрос к модели, неудачная переделка оставляет прежнюю версию.

## Если что-то пошло не так

- Мастер видит «Не получилось: …» у кадра: причина в `tools/media/worker.log`. После трёх неудачных попыток запись помечается как неудавшаяся и оригинал удаляется, мастер снимает заново. Если не удалась переделка, мастер видит прежнюю версию с пометкой «Переделать не получилось».
- Воркер не берёт работу: смотрите `autostart.ps1 status` и доступность `http://127.0.0.1:8081/healthz`.
- Модель не ответила или ответила мусором: сервер берёт запасной план (пресет `clean`, сырые субтитры), обработка не останавливается; в логе сервера есть предупреждение.
