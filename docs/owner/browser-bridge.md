# Связка Claude Code с Chrome

Команды `/content-plan`, `/content-review` и `/instagram-audit` смотрят страницы мастеров через расширение Claude in Chrome в вашем Chrome (профиль `Default`). Расширение общается с Claude Code через «родной хост» (`chrome-native-host.bat` в `~/.claude/chrome`, регистрация в реестре Chrome). Если Chrome не запущен, расширение отключено или хост слетел после обновления, команды не увидят ни одной страницы. Сторож заявок от браузера не зависит: его агент читает страницы без Chrome.

Скрипт `tools/browser/bridge.mjs` следит за связкой и чинит её. Он написан на Node: прежняя версия на PowerShell (`bridge.ps1`) 25.10.2026 была удалена Касперским как троян, потому что сочетала скрытое окно, чтение токена из `server/.env`, отправку в Telegram, перезапуск Chrome и вызов системной библиотеки для измерения простоя. Новая версия тех же приёмов не использует, в карантин её отправлять не за что; если антивирус всё же ругается, не восстанавливайте файл из карантина, а скажите об этом в Claude Code.

## Проверка и починка руками

```
node tools/browser/bridge.mjs check
node tools/browser/bridge.mjs fix
```

`check` проверяет: `claude.exe` на месте, хост зарегистрирован в Chrome и его файлы существуют, расширение установлено в профиле, Chrome запущен, и затем запускает пробный запрос Claude Code (`-p --chrome --restricted`, модель glm-5.3-flash через z.ai, 10–30 секунд), который вызывает инструмент списка вкладок. Ответ расширения значит «связка работает». Результат печатается и пишется в `tools/browser/bridge.log` и `tools/browser/state.json`.

`fix` делает то же и, если связка сломана, запускает Chrome (когда он не запущен) или перезапускает его (вкладки восстанавливаются ключом `--restore-last-session`), затем проверяет снова. Если не помогло, скрипт назовёт причину: чаще всего это снятая регистрация хоста (в Claude Code выполнить `/chrome` и переустановить расширение) или удалённое расширение.

Если Claude Code запущен раньше Chrome, в самой сессии инструменты браузера пишут «not connected»: это лечится `/mcp` и Reconnect, скрипт тут не нужен.

## Автоматическая проверка

```
node tools/browser/bridge.mjs install
```

Ставит задачу `PostHelperBridgeWatch` через общий запускатель `tools/hidden-task.ps1` (без прав администратора, без окна): при входе в систему и дальше раз в час скрипт делает тихую проверку (`run`). Если тоннеля Happ нет, проверка пропускается (тоннелем занимается скрипт запуска Chrome). Что делает автомат при поломке:

- Chrome не запущен: запускает его сам и проверяет снова.
- Chrome запущен, но расширение не отвечает: перезапускает Chrome, только если экран заблокирован (Win+L); пока вы работаете, Chrome не трогает.
- Связка всё ещё сломана: присылает в Telegram сообщение с причиной и командой починки (повтор не чаще раза в 12 часов), а когда связка оживает, сообщает об этом. Telegram берётся из `server/.env`.

Состояние: `node tools/browser/bridge.mjs status`. Снять задачу: `uninstall`. Другой профиль Chrome: ключ `--profile <имя папки профиля>`. Тесты: `node --test "tools/browser/*.test.mjs"`.
