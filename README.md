# Помощник

Личный голосовой помощник: большая кнопка записи, текстовый чат, вложения файлов и фото, озвучка ответов. Фронт: Angular 22 PWA (`web/`). Сервер с Claude: Go (`server/`).

## Что делает приложение

Помощник для мастеров бьюти-сферы, которые ведут Instagram без лишних усилий. Первый этап: знакомство в чате (9 вопросов, текстом или голосом) и стратегия на отдельном экране (позиционирование, правки профиля, рубрики с идеями, ритм публикаций в неделю, первые шаги).

Защита от мусорных ответов: каждый ответ проверяется на месте (слова, а не цифры и значки, нет клавиатурной «каши» и повторов, ник Instagram латиницей), плохой ответ не принимается, бот объясняет и даёт пример. Любой вопрос, кроме «чем занимаетесь», можно пропустить словом «пропустить», команда «назад» возвращает к прошлому вопросу. После последнего вопроса открывается анкета со всеми ответами: их можно поправить, и только кнопка «Всё верно» запускает составление стратегии. Если модель на сервере решает, что данных мало или это бессмыслица, она отказывается (ответ 422), и анкета открывается снова. Позже анкету можно изменить кнопкой «Изменить анкету» на экране стратегии.

Анкета и стратегия хранятся в браузере (`helper.onboarding`, `helper.strategy`); «Пройти знакомство заново» стирает их. Второй этап, календарь (кнопка в шапке и на экране стратегии): мастер выбирает «день контента» (один-два раза в неделю, день и время) и время публикаций, приложение расставляет публикации на 4 недели вперёд по ритму из стратегии (Reels, посты, сторис), чередуя рубрики и идеи; запуск плана идёт со следующего дня. Публикации отмечаются галочкой «Опубликовано». Кнопка «Добавить в календарь телефона» скачивает файл `.ics`: повторяющееся событие «День контента» (уведомление за час) и по событию на каждую неопубликованную будущую публикацию (уведомление за 15 минут). Напоминает календарь телефона, сервер не нужен. План строится на клиенте без запроса к ИИ (`utils/plan-builder.ts`), хранится в `helper.calendar`.

Третий этап, комплекты публикаций: у каждого пункта календаря кнопка «Подготовить комплект» (и «Подготовить комплекты на неделю» по очереди, с прогрессом). Сервер (`POST /api/kit`, пакет `server/internal/kit`) получает анкету, позиционирование и публикацию (формат, рубрика, идея) и возвращает задание на съёмку, кадры с текстом на экране (сцены Reels, слайды поста, кадры сторис), готовую подпись, хэштеги и подсказку. Комплект открывается отдельным окном с кнопками «Скопировать подпись и хэштеги» и «Скопировать весь комплект»; хранится в `helper.kits` и привязан к идее публикации (при пересоставлении календаря лишние комплекты удаляются). Каждый комплект это отдельный запрос к Claude (до 2500 токенов ответа), недельная пачка идёт по одному запросу подряд.

Дальше по плану: перенос анкеты, стратегии, календаря и комплектов в Postgres, контекст анкеты в обычном чате, лимиты расходов на клиента.

## Сервер (из `server/`)

```bash
go run .           # слушает :8080, читает server/.env
go test ./...      # юнит-тесты
```

Переменные окружения (локально можно в `server/.env`, на хостинге в его настройках):

| Переменная | Назначение |
|---|---|
| `ANTHROPIC_API_KEY` | ключ Anthropic, обязателен |
| `ACCESS_PASSWORD` | пароль доступа, не короче 8 символов, обязателен |
| `PORT` | порт, по умолчанию 8080 (хостинг задаёт сам) |
| `ALLOWED_ORIGINS` | адреса фронта через запятую для CORS, по умолчанию Pages и localhost:4200 |
| `HELPER_MODEL` | модель, по умолчанию `claude-sonnet-5-5` |
| `DATABASE_URL` | строка подключения Postgres (Neon) для истории и журнала ошибок, необязательна: без неё сервер работает, но ничего не сохраняет (см. раздел «История и журнал ошибок») |

API: `POST /api/kit` (JSON `{profile, positioning, format: reels|post|stories, pillar, idea}`, ответ `{shots, frames:[{visual, overlay}], caption, hashtags, tip}`), `POST /api/strategy` (JSON анкеты `{specialty, name, city, experience, services, clients, goal, instagram, style}`, обязательно только `specialty`; ответ: `{summary, positioning, profileFixes, pillars, cadence, firstSteps}`, при нехватке данных 422 с пояснением), `POST /api/chat` (multipart: `text`, `history` как JSON `[{role,text}]`, `files`), заголовок `Authorization: Bearer <пароль>`, ответ `{"reply": "..."}`. `GET /healthz` для проверки хостингом. Фронт запоминает пароль в `localStorage` и просит ввести его заново при ответе 401.

Адрес боевого сервера задаётся в `web/src/app/constants/api.constants.ts` (`API_PRODUCTION_URL`), в dev-режиме фронт ходит на `http://localhost:8080`.

## История и журнал ошибок (Postgres)

Сервер пишет в Postgres, если задана `DATABASE_URL` (бесплатная база на Neon, строка вида `postgres://user:pass@host/db?sslmode=require`). Таблицы создаются сами при старте из `server/internal/store/migrations/*.sql` (применённые миграции помнит таблица `schema_migrations`). Запись идёт в фоне: если база недоступна, чат продолжает работать, а в логе сервера появляется предупреждение.

| Таблица | Что хранит |
|---|---|
| `messages` | все реплики чата приложения (`source=app`, беседа = `conversation`, меняется кнопкой «Очистить»); через `POST /api/ingest` можно загрузить реплики из других источников |
| `events` | запросы чата и пакеты загрузки |
| `error_log` | ошибки сервера (всё, что пишется в лог на уровне ERROR, паники) и ошибки приложения в браузере (`source=client`) |

Чтение (заголовок `Authorization: Bearer <пароль>`): `GET /api/history?source=&conversation=&limit=`, `GET /api/events?kind=&limit=`, `GET /api/errors?limit=`. Запись: `POST /api/ingest` (`{source, conversationId, messages:[{externalId, role, text, at}]}`, повтор с тем же `externalId` не создаёт дубль) и `POST /api/client-error`.

## Команды (из `web/`)

```bash
npm start          # dev-сервер http://localhost:4200 (service worker выключен)
npm run build      # боевая сборка в dist/web/browser (service worker активен)
npm test           # юнит-тесты
```

Проверить PWA локально:

```bash
npm run build
npx http-server dist/web/browser -p 4300 -c-1
```

## Версионирование

Версия повышается при каждом коммите хуком `.githooks/pre-commit` (`web/scripts/bump-version.mjs`): правит `web/package.json` и `web/src/app/version.ts`. Хук подключается сам при `npm install` (скрипт `prepare`), либо вручную: `git config core.hooksPath .githooks`.

## Обновления PWA

При каждой загрузке и при возврате на вкладку приложение проверяет новую версию (`AppUpdate`). Найденная версия применяется перезагрузкой, когда пользователь не пишет сообщение, не ждёт ответ и не записывает голос.

## Публикация на GitHub Pages

Workflow `.github/workflows/deploy.yml` собирает `web/` с `--base-href=/<имя-репозитория>/` и публикует на Pages при пуше в `master` или `main`. Pages на бесплатном плане требуют публичный репозиторий. Один раз включить Pages через workflow:

```bash
gh api -X POST repos/StarcevAlexander/post-helper/pages -f build_type=workflow
```

Ключ Anthropic лежит только в `server/.env` (в `.gitignore`) и в переменных окружения хостинга сервера, во фронт и в репозиторий он не попадает.
